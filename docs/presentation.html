Syntaxin

From arbitrary EHR exports to typed, routed, cited tickets for human review. Two checkers over one governed pipeline, under one safety contract.
Problem: in Annual-Wellness-Visit panels, which lab results need a human first — and which expected tests were ordered but never resulted (the loop that silently stays open)?
  • Who it helps & why: high-volume, high-stakes review. The failure mode — a critical result or an unresulted order sitting unseen — is exactly what a ranked, gated queue fixes.
  • Core move: treat the anomaly, not the data, as the universal object — so whatever shape the source takes, each finding becomes one normalized, cited ticket.

Sound data judgment — the messy parts

What I trusted, cleaned, and excluded

  • Trusted (deterministic): each result carries its own reference range, LOINC, flag → out-of-range detection needs no assumptions.
  • Repaired: BP as "150/99" text → split; ragged rows, quoted multi-line notes, values spanning cells → structural repair, logged, never silent.
  • Excluded / gated: sentinels & impossible values kept out of the clinical queue.

The plausibility gate

  • Sodium 178.6 → critical, clinical-urgent
  • Sodium 208 · SpO₂ 126% → impossible → data-quality, diverted from the clinical queue

Clinical appropriateness & safety

Fact vs. hypothesis — and where GenAI does real work

Fact — deterministic, authoritative

  • values, ranges, severities, plausibility, clinical rules
  • the LLM never emits a value, dose, severity, rule, or URL

Hypothesis — advisory, cited, verified

  • Assessment / Plan, citing governed rules + the facts it explains
  • a deterministic verifier rejects unsourced content — it caught its own false-positives (fabricated values, brand≡generic)
GenAI is at the edges (compiling messy schemas → reviewed mapping specs; reasoning over unstructured notes) — not authoring the artifact that touches the human.
  • Human approval gates the action, not the reading. Nothing writes to a chart; every actionable ticket takes a click.
  • Honest by design: when no governed rule applies, the system says so and stays silent rather than speculate.

Biggest risks — and the architecture that contains them

Where it could be wrong, and the guardrails

Risks & mitigations

  • Generic stats ≠ clinical judgment → two tiers: generic stats for data quality, governed rules for clinical validity.
  • Med-recon false positives (a regex mis-parses doses; brand vs generic) → the verified LLM pipeline found the truth: 0 real gaps. Honest > inflated.
  • Out-of-scope data → fail safe: flag low-fit mappings, don't force-fit; generic analyzer still gives a floor.

Architecture

any ASCII source → input connector (discover → load, verified) AI ↔ human-reviewed → canonical model the fixed contract → application layer (registry of checkers) deterministic + governed → cited hypothesis → verify advisory, sourced → tickets → queue human-gated → output connector (dry-run) human-gated write
Connectors at the edges are the durable product; the app layer is swappable. 100+ tests · zero-network demo.

Appendix · A2 — research avenue

Scaling the analysis tier without exploding

Single-signal analysis is a no-brainer. For k-uplets (joining k signals), the space of combinations is a power set — you can't enumerate it.
k=1 single-signal analyzers run (free, immediate) → fast tickets schema + k=1 findings → what's possible × what's interesting k=2 pairwise affinity (|corr|, min co-observation) → O(N²), tractable graph → dominant sets (Pavan–Pelillo, replicator dynamics) → coherent, overlapping cliques cliques = candidate k-uplets → human-curated → governed analysis
Run on the real panel (npm run cliques): it recovered known physiology — Glucose ↔ HbA1c and a Sodium · Creatinine · Urine-ACR renal cluster — with no enumeration; a cohesion gate rejects the incoherent leftover.
  • Higher-order groups are discovered from pairwise structure, not brute-forced. Anticorrelation is as informative as correlation.
  • Cliques are hypotheses, not conclusions — correlation stays a candidate; governed rules + a human decide meaning. (Confounding, support, stratification all apply.)

Appendix · A3

Composable microservices — canonical model as the contract

POST /connect/discover schema discovery (LLM) + quick sample round-trip POST /connect/load full-dataset load + verify; manifest bypasses the LLM; a failed induced mapping is repaired — the specific failing fields are fed back to the model, not re-rolled blindly POST /analyze canonical dataset → registry of analyzers → tickets POST /publish tickets → target field-map → dry-run (human-gated)
  • Each stage is independently callable; the canonical model is the stable interface between them.
  • Isolating the output connector encodes the write-safety boundary — nothing reaches a chart except through the one human-gated endpoint.

Appendix · A4

Data-agnostic, not data-blind — and a governance spectrum

Agnostic input, aware analysis

  • Agnostic to form (any format/schema → canonical) — the connector.
  • Aware of content — an analyzer runs only if its entities are present; unknown data → clinical analyzers sit out, the generic one still runs.

Who decides an analysis runs

  • Human-authored requirements — fully governed
  • AI-suggested, human-validated — nothing runs unreviewed
  • Requirement-free (*) — generic, runs on anything
Autonomy in applicability never becomes autonomy in action — every result still flows through verify → tickets → human gate.
